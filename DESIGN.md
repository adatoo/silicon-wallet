# Silicon Wallet — Design

A free, open-source secrets manager for macOS, iPadOS and iOS, built in Swift/SwiftUI.
It replaces Acrylic Software's *Wallet* (last version 3.5, 2017; Intel-only, unmaintained).

Status: design agreed; project set up; App Store name reserved (Apple ID 6824181307); Acrylic
Wallet's `.wallet` format reverse-engineered, no SEE licence needed (ADR-0005); build steps 1
(crypto), 2 (model, `VaultSession`), 3 (local store), 4 (UI), 5 (lock UX), 6 (sync) and 7
(attachments) done. Next: build step 8.

## 1. Goals

1. Free and open source (MIT licence).
2. Free on the Mac App Store and iOS App Store (one universal purchase).
3. Mac, iPad and iPhone from one codebase.
4. iCloud sync, end-to-end encrypted.
5. Import from Acrylic Wallet (later phase; see §9).
6. Functional parity with Acrylic Wallet: flexible groups with custom field templates,
   entries, notes, attachments, search, lock/unlock, auto-lock, clipboard clearing, access log.
7. Name: **Silicon Wallet**. Avoid Acrylic's name, icon, artwork and code.
8. Swift / SwiftUI only.

### Non-goals (v1)
- Browser extensions and Password AutoFill (phase 3).
- Sharing a vault between people.
- Android, Windows, web.

## 2. Platform decisions

| Decision | Choice |
|---|---|
| Minimum OS | iOS 26 / iPadOS 26 / macOS 26 |

## 3. Architecture

```
silicon-wallet/
├─ project.yml                     # XcodeGen source of SiliconWallet.xcodeproj
├─ SiliconWallet.xcodeproj         # one multiplatform app target (iOS, iPadOS, macOS)
├─ App/                            # SwiftUI app: scenes, views, platform glue
│  ├─ Shared/                      # NavigationSplitView UI, view models
│  ├─ macOS/                       # menu commands, Settings scene, sleep/screensaver lock
│  └─ iOS/                         # scene-phase lock, iPhone-specific bits
└─ Packages/SiliconWalletKit/      # all non-UI logic, fully unit-tested
   ├─ Crypto/                      # KDF, vault key, AEAD, key wrapping
   ├─ Model/                       # plaintext domain types (in memory only)
   ├─ Store/                       # SwiftData encrypted records + attachment files
   ├─ Sync/                        # CKSyncEngine delegate, record mapping, conflicts
   └─ Vault/                       # VaultSession: unlock/lock, CRUD, search
```

Rule: **the app target never touches ciphertext or CloudKit directly**. It talks to
`VaultSession` in SiliconWalletKit, which exposes plaintext domain objects only while unlocked.

### UI
- `NavigationSplitView` with three columns: **Groups | Entries | Detail**.
- Mac and iPad show all three columns. iPhone collapses to drill-down navigation.
- Toolbar: lock toggle, sync status, search. Bottom/toolbar actions: add group, add entry, edit.
- Original look and icon. Do not copy Acrylic's artwork. The icon (a silicon chip with a keyhole,
  teal to navy) is drawn by `scripts/make-icon.swift`; run `task icon` after changing it.
- The lock screen has a backdrop: a blurred close-up of a circuit board in the icon's colours,
  original artwork drawn by `scripts/make-backdrop.py` (`task backdrop`), with the form on a
  frosted card. Only the lock screen has it; the vault screens keep the system backgrounds.
- Sidebar: All Entries, Favourites, then the groups (drag to reorder). Moving an entry to
  another group keeps every value: matching labels move across, the rest become extra fields.
- Entry list: A–Z sections by the title's first letter (accents removed, leading punctuation
  skipped, digits and symbols under "#", last), with the iOS section index. "Group by First
  Letter" (on by default) is in the list's View Options menu and the Mac View menu; it's a
  display preference kept in `UserDefaults`.
- Entries show as a list (three columns) or as cards (View Options menu; Mac View menu ⌘1 / ⌘2).
  Cards mode is two columns, Groups | cards, so the cards get the width. A card shows the group
  icon, title, first non-concealed value, group and favourite star, never a concealed value.
  Opening a card shows the entry in a sheet with the same detail view, Done and Edit; the sheet
  follows edits and closes if the entry is deleted or the vault locks.
- Mac shortcuts: ⌘N new entry, ⇧⌘N new group, ⌘E edit, ⌘1 / ⌘2 list / cards, ⌃⌘L lock.
- Launch arguments `-InMemoryVault -DemoVault` (optionally `-Locked`) open a throwaway vault
  filled with obviously fake entries, for UI tests and screenshots. `-entryLayout cards` shows
  the card view for that launch.

## 4. Data model (plaintext, in memory only)

```swift
struct FieldTemplate { id: UUID; label: String; kind: FieldKind; isConcealed: Bool }  // order = array order
enum FieldKind { text, password, number, date, url, email, phone, multiline }

struct VaultGroup {   // "Vault" prefix avoids clashing with SwiftUI's Group
  id: UUID; name: String; icon: String; fields: [FieldTemplate]; order: Int; modified: Date
}

struct VaultEntry {
  id: UUID; groupID: UUID; title: String
  values: [UUID: String]          // FieldTemplate.id -> value
  extraFields: [CustomField]      // per-entry fields not in the group template
  notes: String; isFavorite: Bool
  attachments: [AttachmentRef]
  created: Date; modified: Date
}

struct AttachmentRef {
  id: UUID; filename: String; uti: String; size: Int64
  fileKey: SymmetricKey (256-bit, random per file); sha256: Data
}
```

Field labels live on the group, so "Gate Information" can have `side gate`, `main gate`, `other`.

The code is in `SiliconWalletKit/Model`. `VaultMeta` (KDF parameters, wrapped vault key, a
key check that proves a biometric-held vault key belongs to this vault, format version) is the
only unencrypted vault data. New vaults start with editable groups: Logins, Credit Cards, Bank
Accounts, Software Licences and Secure Notes.

## 5. Security

### Key hierarchy
1. **Master password** → Argon2id (random 16-byte salt; parameters stored with the vault,
   tuned to about 0.5 s on the slowest supported device; starting point 64 MiB, 3 iterations) → **KEK**.
   libsodium's `crypto_pwhash` (ADR-0006). The password is normalised to Unicode NFC first, so
   precomposed and decomposed forms of the same password unlock the same vault.
2. **Vault key**: random 256-bit key generated at vault creation. Stored only wrapped
   (AES-GCM) under the KEK. Changing the master password re-wraps the vault key only.
3. **Record encryption**: every Group and Entry is serialised (Codable → binary plist/JSON)
   and sealed with AES-256-GCM under the vault key. The record ID is used as associated data
   (AAD), so ciphertext can't be swapped between records.
4. **Attachments**: each file is sealed with its own random file key. That key is stored inside
   the owning Entry's encrypted payload.
5. **Sealed-value format** (`SiliconWalletKit/Crypto/Envelope.swift`), used for the wrapped
   vault key, records and attachments: `version (1 byte) ‖ nonce (12) ‖ ciphertext ‖ tag (16)`.
   The nonce is random. The associated data is the version, a purpose label (`vault-key`,
   `record`, `attachment`) and, for records and attachments, the owning ID. So a sealed value
   can't be opened as a different kind of value or under a different ID.

### What is stored unencrypted
Record ID, record type, modified timestamp, schema version, ciphertext length.
Nothing else: names, labels, values, notes and filenames are always encrypted.

### Unlock and lock
- Master password unlock is always available.
- Face ID / Touch ID: the vault key is stored in the Keychain with
  `.biometryCurrentSet`, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, never synced.
  Require the master password after a restart, and after a configurable period (default 7 days).
  The vault key is checked against `VaultMeta.keyCheck` before use; a key that doesn't match
  (or an item invalidated by a biometry change) turns biometric unlock off. Settings: lock after
  inactivity, lock on sleep (Mac) or after time in the background (iOS), clipboard clearing,
  biometrics and the re-entry period; stored in `UserDefaults`, never anything secret.
  On the Mac, Touch ID is part of the lock screen (`LocalAuthenticationView`), not a floating
  panel: the screen's `LAContext` is approved with Touch ID, then reused for the Keychain read so
  there's no second prompt. Typing the password stops it. iOS uses the system Face ID prompt.
- Auto-lock: after inactivity (default 5 min). On macOS also on sleep, screensaver and
  screen lock. On iOS when backgrounded (configurable grace period).
- On lock: discard decrypted models, zero key material where possible, delete temporary
  preview files, clear our own clipboard items.
- Attachments: images, PDFs and text preview from memory. Other types open in Quick Look from
  a decrypted temporary file (complete file protection on iOS), deleted when the preview
  closes, on lock and at launch. "Save a Copy…" writes an unencrypted copy where the person
  chooses.

### Everyday protections
- Concealed fields hidden until revealed.
- Copy to clipboard with auto-clear (default 60 s). On iOS use local-only, expiring pasteboard
  items. On macOS mark items as concealed / transient.
- Password generator (random characters and word-based): `PasswordGenerator`, with a built-in
  list of about 1,660 common words (about 10.7 bits each; six words by default).
- Access log (encrypted, local per device): unlocks, failed attempts, exports.
  `AccessLog` seals it under the vault key, capped at 1,000 events. Failed attempts happen while
  locked, so they wait in a pending file of event kinds and times only (no names, nothing
  typed) and are sealed in at the next unlock. Shown in Settings ▸ Access Log.
- Delete Vault (Settings, needs the master password): from iCloud and every device (deletes the
  zone), or this device only. A zone deleted on purpose elsewhere (`.deleted`, `.purged`) removes
  the vault here too; `.encryptedDataReset` re-uploads it.
- Screenshot / screen-recording privacy cover on iOS app switcher.
- Never log secrets. No plaintext ever written to disk, iCloud, caches or crash logs.

## 6. Local storage

- SwiftData container, **no CloudKit option**, in the app's sandbox container.
- `@Model` types are ciphertext envelopes only (`SiliconWalletKit/Store`, `SwiftDataVaultStore`):
  - `VaultMetaRecord`: format version and the encoded `VaultMeta` (KDF params, salt, wrapped
    vault key, key check), plus CloudKit system fields.
  - `SealedRecordModel`: one table for groups and entries. Its columns are id, kind, modified,
    schema version, ciphertext and system fields; an entry's groupID lives inside its ciphertext.
  - `AttachmentRecord` (id, size, local file state, system fields; the owning entry is known
    only inside that entry's ciphertext).
- The store is `Application Support/com.datoos.silicon-wallet/Vault/Vault.store`. Attachment
  ciphertext is stored as files under `…/Vault/Attachments/<uuid>.bin`.
- File protection: `.complete` on iOS.

## 7. iCloud sync (CKSyncEngine)

- CloudKit **private database**, custom zone `Vault`.
- Record types: `VaultMeta`, `Group`, `Entry`, `Attachment`.
- Each record's encrypted payload goes in a field set via `CKRecord.encryptedValues`
  (CloudKit's own encryption layered on top of ours).
- Entries and groups sync eagerly, so every device has the full encrypted vault and search
  works offline.
- **Attachments**: stored as a `CKAsset` on a separate record, outside the eager sync stream,
  and downloaded on demand when first opened, then cached encrypted. Mac setting:
  "Keep all attachments offline".
- Per-file size limit (start at 100 MB) and iCloud usage shown in Settings.
- **Conflicts**: on `serverRecordChanged`, decrypt both versions; the later `modified` wins
  and the other is saved as an entry titled "<title> (conflict copy, <device>, <date>)".
- New device: fetch `VaultMeta`, ask for the master password, unwrap the vault key, then sync.
- Sync engine state serialization persisted locally; account-change and zone-deleted
  events handled (e.g. sign-out → keep local data, pause sync, show status).
- **As built** (`SiliconWalletKit/Sync`): `SyncedVaultStore` wraps the local store and queues
  every change `VaultSession` makes, so the session doesn't know sync exists; `VaultSync` writes
  fetched records to the underlying store and asks the session to reload. Each record keeps its
  CloudKit system fields. Plain fields are only `modified`, `schemaVersion`/`formatVersion` and
  an attachment's size; payloads are in `encryptedValues`, attachments are `CKAsset`s of their
  sealed files.
  - Conflict copies need the vault key, so they're made only while the vault is unlocked;
    while locked, the later version simply wins. A tie goes to the server.
  - `zoneNotFound`/`unknownItem` re-upload the item; a deleted zone re-uploads everything.
  - First run waits (up to 20 s) for iCloud's first fetch before offering to create a vault, so
    a new device joins the existing vault instead of starting a second one.
  - v1 downloads attachments with the rest of the vault rather than on demand; on-demand
    download and the "Keep all attachments offline" setting are later work.
  - Sync runs only in builds signed with the iCloud entitlement; ad-hoc `task dev` builds,
    tests and the demo vault stay local.

## 8. Build order

1. SiliconWalletKit: crypto (KDF, wrap/unwrap, seal/open) with unit tests and test vectors.
2. Domain model and `VaultSession` (create vault, unlock, lock, CRUD, search) with tests.
3. Local SwiftData store and attachment file store.
4. SwiftUI three-column UI: groups, entries, detail, editing, group field-template editor.
5. Lock UX: password, biometrics, auto-lock, clipboard clearing, generator.
6. `CKSyncEngine` sync of meta, groups and entries, plus conflicts.
7. Attachments: add, preview (Quick Look), on-demand download.
8. Settings, access log, polish, accessibility, App Store assets.

## 9. Later phases

- **Import from Acrylic Wallet**. The route is decided (issue #1, ADR-0005): **Silicon Wallet
  reads `.wallet` files natively**, no SEE licence and no copy of Wallet.app needed.
  - A `.wallet` file is a SQLite database encrypted with the commercial SQLite Encryption
    Extension (SEE). Black-box known-plaintext analysis of fake fixtures (no disassembly,
    no SEE source, no Acrylic code) recovered the scheme in full: AES-256-OFB, key =
    `"W7f@" + password` repeated/truncated to 32 bytes, per-page IV = the page number as a
    little-endian `UInt32` zero-padded to 16 bytes, no per-file salt. See ADR-0005 and
    `Fixtures/AcrylicWallet/README.md` for how this was found.
  - `SiliconWalletKit`'s `AcrylicImport` module (`AcrylicWalletReader`) implements this with
    CommonCrypto and the system `libsqlite3`, decrypting only into memory, and is unit-tested
    against every fixture in `Fixtures/AcrylicWallet/`.
  - **Built (2026-10-18):** `AcrylicImporter` maps groups, field templates, entries, notes,
    favourites, dates and attachments into Silicon Wallet's model (ADR-0005), and the app has
    "Import from Acrylic Wallet…" (File menu, Settings, the empty vault, and a setup option
    that skips the starter groups). Choose the file, enter its old password, check the preview,
    import. The old file is never changed or deleted; the summary suggests deleting it once
    checked. Wallet's CSV/TSV exports remain a secondary, lossy fallback.
  - Wallet.app 3.5 is Intel-only and needs Rosetta, which runs general apps only up to macOS 27
    (autumn 2027). Reading `.wallet` natively, rather than depending on Wallet.app, is what
    keeps import working after that.
  - Fixtures are fake vaults made on a Mac that never held a real vault; the real vault is
    never touched by this code.
- Export: encrypted backup file plus optional plaintext CSV/JSON with warnings.
- Password AutoFill extension (iOS, iPadOS, macOS).
- Widgets / Apple Watch (maybe).
